# AI Humanizer

Use this skill to:

- reduce AI-generated writing patterns
- make technical articles sound more natural
- improve engineering authenticity
- simulate experienced developer expression

## Core Goal

The article should feel like:

- a real engineer's sharing
- project experience accumulation
- practical technical review
- architecture discussion

Not:

- AI summary
- textbook explanation
- official documentation rewrite
- generic tutorial

## Rewrite Rules

Reduce:

- repetitive sentence structures
- “首先/其次/最后”
- excessive transitions
- over-formal explanation
- rigid markdown rhythm

Prefer:

- natural engineering narration
- practical troubleshooting language
- realistic technical reflection
- concise explanations
- project-driven thinking

## Engineering Expression Style

Prefer expressions like:

- “这个问题本质上是…”
- “实际项目里这里很容易踩坑”
- “一开始我也用了…但后面发现…”
- “真正影响性能的其实是…”
- “这里需要特别注意…”
- “企业项目里一般不会这么做…”

Avoid:

- “下面让我们来…”
- “通过以上内容可以看出…”
- “总的来说…”
- “综上所述…”
- “本文详细介绍了…”

## Technical Discussion Style

Encourage:

- tradeoff analysis
- architecture thinking
- practical constraints
- engineering compromise
- performance discussion

## Sentence Rhythm

- Sentence length should vary naturally
- Avoid robotic consistency
- Allow concise technical statements
- Avoid overly polished transitions

## Humanization Strategy

Inject:

- engineering judgment
- implementation experience
- troubleshooting mindset
- practical caveats
- production considerations

## Important Rule

Do not over-humanize.

The goal is:

- professional engineer tone

Not:

- casual blogging
- emotional storytelling
- exaggerated personality

## Tone

Senior frontend engineer / GIS engineer style.
